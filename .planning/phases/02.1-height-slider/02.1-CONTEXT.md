<domain>
## Phase Boundary

Replace the ArUco-Dial ID-10 input for the HEIGHT state of the canonical content FSM with a physical DollaTek 10K linear-slide potentiometer wired to the existing ESP32-RFID's ADC pin. The slider position quantizes to N discrete floors (1..max_floors per construction method), is transported over the same USB Serial pipe @115200 baud that already carries RFID method selection, and is surfaced to TouchDesigner as a Serial DAT-stored value the existing `vision2_state_chop.py` Script CHOP exposes as named channels.

**Untouched by this phase:**
- Closed-loop CV (red-puck footprint detection, RFID method selection, gesture recognition).
- WiFi/OSC paths (slider stays Serial-only; `osc_bridge.py` and `vision_in` OSC In CHOP unchanged).
- Existing `RFID:<HEX>` and `HB:<sec>` line formats on the same Serial port.

</domain>

<decisions>
## Implementation Decisions

### Hardware
- **Sensor:** DollaTek "10K Modulo de potenciometro Lineal Deslizante" (Amazon ASIN B07HBWQGYP) — linear slide potentiometer module, breadboard-friendly 3-pin connector.
- **Host MCU:** existing ESP32-RFID board (`firmware/esp32-rfid/esp32_rfid/esp32_rfid.ino`). No second ESP32, no WiFi added.
- **ADC pin:** GPIO34 (ADC1_CH6 — WiFi-safe, input-only). Attenuation `ADC_11db` → 0..3.3 V mapping.
- **Wiring:** slider VCC → 3V3, GND → GND, wiper → GPIO34. Shares the 3.3 V rail with the RC522.

### Transport
- **Protocol:** existing USB Serial @115200 baud (CDC), single direction ESP32 → TouchDesigner.
- **New line prefixes** (orthogonal to existing `RFID:<HEX>` and `HB:<sec>`):
  - `FLOOR:<int>` — emitted on quantized floor change.
  - `SLIDER:<0.xxx>` — emitted periodically (~200 ms) for debug + alive check, even when floor unchanged.
- **Heartbeat reuse:** `HB:<sec>` covers both RFID and slider liveness — one device, one heartbeat. No new heartbeat line needed.

### Signal conditioning (firmware-side)
- **ADC sampling:** poll every ~50 ms inside the existing `loop()`.
- **Smoothing order:** median FIRST (8-sample window — kills single-tick spikes), EMA SECOND (alpha 0.2 starting point — tune in jitter test). Reversing the order lets a spike pull the EMA.
- **Quantization:** `floor = 1 + round(smoothed_norm * (MAX_FLOORS - 1))`, where `smoothed_norm` is in [0, 1].
- **Hysteresis:** floor only changes when `abs(smoothed_norm - last_floor_center) > (1 / (2 * (MAX_FLOORS - 1))) + EPSILON` (EPSILON ~= 0.02). No oscillation at boundaries.
- **`MAX_FLOORS`:** `constexpr uint8_t` at the top of the sketch, initial value 5. Per-method caps live TD-side (in `methods_db.json`), not firmware-side.

### TouchDesigner parsing
- File: `touchdesigner/scripts/serial_rfid_v1.py`.
- `onReceive` gets two new branches alongside existing `RFID:` and `HB:`:
  - `FLOOR:` -> strip prefix, `int(...)`, `dat.store('floor', value)`.
  - `SLIDER:` -> strip prefix, `float(...)`, `dat.store('slider_raw', value)`, and stamp `dat.store('slider_last_frame', absTime.frame)` for liveness.
- `onConnect` and `onDisconnect` reset defaults: `floor = 1`, `slider_raw = 0.0`, `slider_last_frame = -1`.

### TouchDesigner state aggregation
- File: `touchdesigner/scripts/vision2_state_chop.py` (current canonical `compute_state`). `state_chop_v1.py` stays untouched (deprecated reference).
- Three new output channels:
  - `floor` (int, default 1) — `op('rfid_in').fetch('floor', 1)`.
  - `slider_raw` (float, default 0.0) — `op('rfid_in').fetch('slider_raw', 0.0)`.
  - `slider_alive` (int, 0/1) — derived from `slider_last_frame` staleness vs `me.time.frame` (timeout ~= 60 TD frames, ~2 s at 30 fps).
- Existing `method_id`, `hb_alive`, `puck_count`, etc. left intact.

### FSM input
- HEIGHT state input switches from "ArUco dial ID-10 rotation" to `op('compute_state')['floor'][0]`.
- ArUco ID-10 (`cad/aruco-markers/aruco_id10_height.png`) is retired from active runtime. PNG/CAD asset stays on disk for archive but is no longer expected by the vision pipeline.
- **Floor-cap validation:** when `floor > methods_db.json[method_id].max_floors`, the FSM emits `INVALID` visual-feedback state (per existing visual-feedback machinery in `footprint_viz_v5.py`) and pauses HEIGHT confirmation until the slider moves below the cap.

### Data
- `data/methods_db.json` gets a `max_floors` integer per method:
  - masonry: 5
  - 3d_printed (earth-based): 1 (locked decision — earth 3DP max 1 story, see `.planning/PROJECT.md`)
  - prefab: 4
  - reclaimed_brick: 5 (baseline toggle inherits the active method's cap; documented in JSON comment)
- Field is **additive**, read lazily. No schema-migration / `lca_data_reader.py` change required.

### Contracts and specs
- **`INTERFACE_CONTRACT.md` Section 9** (Sensor / ESP32 Input Contract) extended:
  - New required fields: `floor` (int, 1..N), `slider_raw` (float, 0..1), `slider_online` (bool).
  - New "current live messages" subsection listing `FLOOR:` and `SLIDER:` line prefixes alongside `RFID:` and `HB:`.
- **`INTERFACE_CONTRACT.md` Section 4** (Current Working TouchDesigner Contract) extended with the new `compute_state` channels.
- **`.planning/FSM_TOUCHDESIGNER_SPEC.md`:** HEIGHT state Input row updated from "ArUco dial ID-10 rotation" to "Serial `floor` channel from ESP32 slider, validated against method's `max_floors`".

### Verification path
- **Demo loop:** slider movement (full sweep) -> TD textport prints `FLOOR:N` transitions and `SLIDER:0.xxx` ticks; `compute_state['floor']` updates within 100 ms; stats overlay (`stats_text` Text TOP via `panel_text.py`) shows current floor count.
- **Jitter test:** hold slider at a known boundary for >= 5 s; `floor` channel must NOT oscillate.
- **Cap test:** pick `3d_printed` via RFID, drag slider above 1; visual-feedback state goes `INVALID` and HEIGHT does not confirm.

### Claude's Discretion
- Exact median window size (defaulted to 8 — can drop to 5 if firmware loop budget gets tight).
- Exact EMA alpha (0.2 is a starting point — tune in the jitter test).
- Whether to emit `SLIDER:` every 200 ms or piggyback on the existing `HB:` cadence (1 s). Default to 200 ms for low TD-side latency.
- Internal storage: `dat.store('slider_last_frame', ...)` vs. a separate CHOP — pick whichever stays simplest in the existing `onReceive` shape.
- Exact wave / task split for the planner (firmware before TD parsing? Parallel? Doc updates last?).

<specifics>
## Specific Ideas

- Use `analogReadMilliVolts(GPIO34)` (ESP32 Arduino core >= 2.0) rather than raw `analogRead` — already gives a calibrated mV reading and avoids ADC non-linearity headaches near rails.
- For the median, keep a small ring buffer (size 8) on the stack and `std::nth_element` on n/2 — cheaper than a full sort.
- Median FIRST, EMA SECOND. Reversing it lets a single spike contaminate the smoothed value.
- Hysteresis pattern: `if abs(smoothed_norm - last_floor_center) > (1 / (2 * (MAX_FLOORS - 1)) + EPSILON): recompute floor` with `EPSILON ~= 0.02`.
- The OSC-naming-convention auto-detection block in `vision2_state_chop.py` (lines ~95-118) is unrelated to Serial reads — keep slider parsing in a separate branch that does NOT touch that detection.
- The Serial DAT (`rfid_in`) does not natively expose a "last-message-frame" — store one via `dat.store('slider_last_frame', absTime.frame)` inside the `SLIDER:` branch of `onReceive`. Read it back in `vision2_state_chop.py` via `op('rfid_in').fetch('slider_last_frame', -1)`.

</specifics>
